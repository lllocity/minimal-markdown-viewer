# Step W09: ドキュメント統合（README / SPEC を iOS版・Web版に）

## 目的

`README.md` と `SPEC.md` が iOS 版のみの記述だったのを、**iOS 版・Web 版の2実装**を扱う内容に統合する。
「読む専用ビューアという思想は共通、到達手段（＝必要な認証・ブラウズ）はプラットフォームで異なる」を明確にする。

## 前提条件
- W08 まで完了（Web 版が本番稼働している）。

## 手順（実施内容）

### 1. `README.md`（入口・簡潔）
- 冒頭を「iOS アプリと Web アプリの2実装」に変更。Web の公開 URL を明記。
- **設計思想**（共通）を残す。
- **2つの実装**の比較表を追加（開き方・認証・ブラウズ・レンダリング・言語基盤・配布）。
- 機能・技術スタックを iOS / Web の小見出し（または列）で併記。
- ドキュメントリンクを `docs/ios/` / `docs/web/` / `docs/web/ROADMAP.md` に更新。

### 2. `SPEC.md`（共通 + プラットフォーム別の3部構成に再編）
- **第1部 共通**: 目的と背景 / 設計思想 / スコープの考え方。
  - 「共通で実装しない」もの（編集・共有・画像・md 以外）と、
    **プラットフォームでスコープが異なる点**（iOS は認証/ブラウズ不要、Web は意図的に IN）を明記。
- **第2部 iOS 版仕様**: 既存内容（onOpenURL / UTI・Document Types / DocumentViewModel /
  MarkdownView / エラー / 制約）を保持しつつ整理。技術スタックは実装済みの `swift-markdown-ui` 2.4.1 に更新。
- **第3部 Web 版仕様**（新規）: 技術スタック / スコープ / アーキテクチャ（`web/` 構成）/
  データフロー（ログイン→ブラウズ→表示）/ 並び順 `sortEntries` / エラー / Vercel デプロイ / テスト方針。

### 3. ロードマップ更新
- `docs/web/ROADMAP.md` の W09 を「完了 ✓」に。

## 確認ポイント（どうなれば成功か）
- README だけ読めば「iOS と Web の2実装があり、思想は共通・手段が違う」と分かる。
- SPEC が共通 / iOS / Web の3部に分かれ、Web 版の仕様（認証・ブラウズ・並び順・デプロイ・テスト）が読める。
- iOS の OUT に挙がる「認証・ブラウザ」が Web では IN である理由（到達手段の違い）が説明されている。
- リンク切れがない（`docs/ios/` `docs/web/` `ROADMAP.md` `step-w08`）。

## 学んだこと・メモ
- 2実装を1つの README/SPEC にまとめる鍵は「**共通の思想**」と「**プラットフォーム固有の手段**」を分けて書くこと。
  スコープ表（IN/OUT）は共通部分と固有部分を分離すると、iOS の OUT と Web の IN が矛盾なく共存できる。
- README は入口として比較表で差分を一望できるようにし、詳細は SPEC / docs に委ねる構成にした。
