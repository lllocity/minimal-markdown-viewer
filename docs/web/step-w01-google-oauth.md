# Step W01: Google Cloud で OAuth 設定

## 目的

Web 版が「Google アカウントでログインして、その人の Google Drive を読む」ために必要な
**OAuth クライアント**（アプリの身分証）を Google Cloud 上に作成する。

このステップのゴールは、次の 2 つの値を手に入れること：

- **クライアント ID**（`AUTH_GOOGLE_ID` に入れる。公開してよい情報）
- **クライアントシークレット**（`AUTH_GOOGLE_SECRET` に入れる。サーバーだけが持つ秘密。Git に絶対コミットしない）

> 用語メモ
> - **OAuth（オーオース）**: パスワードを渡さずに「Drive を読む権限」だけをアプリに与える仕組み。
> - **スコープ**: アプリが要求する権限の範囲。今回は `drive.readonly`（Drive の**閲覧のみ**）。
> - **同意画面（consent screen）**: ユーザーが「このアプリに Drive 閲覧を許可する」と押す画面。
> - **リダイレクト URI**: ログイン成功後に Google が戻ってくる、このアプリ側の URL。

## 前提条件

- Google アカウントを持っている（`.md` を置いている Drive のアカウント）。
- ブラウザで https://console.cloud.google.com にアクセスできる。

## 手順

### 1. プロジェクトを作る
1. https://console.cloud.google.com を開く。
2. 画面上部のプロジェクト選択 → **新しいプロジェクト** → 名前を `minimal-markdown-viewer` などにして作成。
3. 作成後、そのプロジェクトが選択されていることを確認。

### 2. Google Drive API を有効化
1. 左メニュー **API とサービス → ライブラリ**。
2. 「Google Drive API」を検索 → 開く → **有効にする**。

### 3. OAuth 同意画面を設定
1. 左メニュー **API とサービス → OAuth 同意画面**。
2. User Type は **外部（External）** を選択 → 作成。
3. アプリ情報を入力：
   - アプリ名: `Minimal Markdown Viewer`
   - ユーザーサポートメール: 自分のメール
   - デベロッパー連絡先メール: 自分のメール
4. **スコープ** の画面で **スコープを追加** →
   `https://www.googleapis.com/auth/drive.readonly` を追加して更新。
   - これは Google の「**制限付きスコープ**」。**未検証アプリ + テストユーザー登録（最大 100 人）なら審査なしで動く**。個人利用なら審査は不要。
5. **テストユーザー** の画面で、**自分の Google アドレスを追加**（例: yoshijun1024@yahoo... ではなく、Drive を使っている Google アカウントのアドレス）。
   - ここに登録したユーザーだけがログインできる（審査前の状態）。
6. 保存して戻る。「公開ステータス」は **テスト中（Testing）** のままで OK。

### 4. OAuth クライアント ID（Web アプリ）を作成
1. 左メニュー **API とサービス → 認証情報（Credentials）**。
2. **認証情報を作成 → OAuth クライアント ID**。
3. アプリケーションの種類: **ウェブ アプリケーション**。
4. 名前: `mmv-web` など。
5. **承認済みの JavaScript 生成元** に以下を追加：
   - `http://localhost:3000`
6. **承認済みのリダイレクト URI** に以下を追加：
   - `http://localhost:3000/api/auth/callback/google`
   - （本番の Vercel ドメインは W08 で分かってから追加します。今はローカルだけで OK。）
7. 作成すると **クライアント ID** と **クライアントシークレット** が表示される。両方コピーしておく。

## 確認ポイント（どうなれば成功か）

- 「認証情報」ページに **OAuth 2.0 クライアント ID**（種類: ウェブ アプリケーション）が 1 つできている。
- 手元に **クライアント ID** と **クライアントシークレット** の 2 つの文字列がある。
- OAuth 同意画面のスコープに `.../auth/drive.readonly` が入っている。
- テストユーザーに自分の Google アカウントが入っている。

> 取得した 2 つの値は、W02 以降で `web/.env.local` に設定します（Git には含めません）。
> Claude（アシスタント）に値そのものを貼る必要はありません。「取得できた」と教えてもらえれば次に進めます。

## よくあるエラーと対処法

| 症状 | 原因 / 対処 |
|------|------|
| ログイン時 `403: access_denied` | 同意画面の **テストユーザー**にそのアカウントが未登録。テストユーザーに追加する。 |
| `redirect_uri_mismatch` | リダイレクト URI が完全一致していない。`http://localhost:3000/api/auth/callback/google` を末尾まで正確に登録。 |
| スコープに drive.readonly が出ない | Drive API が未有効。手順 2 をやり直す。 |

## 学んだこと・メモ

- iOS 版は「認証なし・ブラウズなし」を意図的に選んだ設計だったが、Web 版は Google ログイン + Drive ブラウズを担うため OAuth が前提になる。
- `drive.readonly` は閲覧専用スコープ。書き込み・編集はしない（SPEC の「読むだけ」思想を Web でも踏襲）。
- シークレットは絶対に Git にコミットしない（`web/.env.local` は `.gitignore` 対象にする）。
